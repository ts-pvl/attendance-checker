# Қызметкерлерге арналған нұсқаулық

[English](staff-runbook.md) · [Русский](staff-runbook.ru.md) · **Қазақша**

Әкімші панелі: `http://<сервер>:8080/admin` (тек мектеп желісінен, оқу
компьютерлерінен ашылмайды).

Панель орыс немесе ағылшын тілінде жұмыс істейді. Бұл нұсқаулықта батырмалар
мен беттердің атаулары панельдегідей орысша жазылған, жақшада қазақша
мағынасы берілген.

Интерфейс екеу. Жоғарғы оң жақтағы ауыстырғыш бірінен біріне өткізеді, ал
келесі кіргенде соңғы қолданылғаны ашылады.

* **Дашборд** (жаңа): сағаттар, қатысып отырған оқушылар, сағат пен апта
  күндері бойынша жүктеме, қатысу матрицасы және таңдалған кезеңдегі барлық
  оқушылар кестесі (әдепкіде ағымдағы апта; матрицаның өз кезеңі бар,
  әдепкіде ағымдағы ай). Қойындылары: «Ученики» (Оқушылар), «Аномалии»
  (Аномалиялар) және «Журнал» (тек әкімшілерге). Әрекеттері ескі беттердегідей.
* **Админка** (ескі): «Сегодня» (Бүгін), «Часы» (Сағаттар), «Ученики»,
  «Аномалии» және «Журнал». Төменде осы беттер сипатталған.

## Таңертеңгі тексеру (30 секунд)

**«Сегодня»** бетін ашып, жоғарыдағы төрт карточкаға қараңыз:

| Карточка | Бәрі дұрыс | Анықтау керек |
|---|---|---|
| Последний сигнал от ПК (компьютерден соңғы сигнал) | бірнеше минут бұрын (жұмыс уақытында) | сыныпта оқушылар болса да, бірнеше сағат бұрын |
| Последняя отметка (соңғы белгілену) | бүгін | оқушылар келсе де, кешеден бері ештеңе жоқ |
| Бот последний раз связывался с Telegram (боттың Telegram-мен соңғы байланысы) | бір минутқа жетпейтін уақыт бұрын | қызыл қате немесе «никогда» (ешқашан) |
| Открытых посещений (ашық келулер) | сыныпта отырғандармен сәйкес келеді | — |

Компьютерлер кестесіндегі сары жолдар — сеансы бар, бірақ белгіленбеген
компьютерлер. Сол оқушыларға кодты сканерлеуді ескертіңіз.

Бірдеңе дұрыс болмаса, қызметтің жұмыс істеп тұрғанын тексеріңіз («Қайта
іске қосу» бөлімі). Ақау кезінде жазылмай қалған келулерді түзету ретінде
енгізіңіз (төменде).

## Жиі орындалатын жұмыстар

**Оқушылар тізімін импорттау немесе жаңарту.** «Ученики» → «Импорт или
обновление из CSV». Бағандар: `имя`/`ФИО` (немесе `name`), `группа` (немесе
`group`), міндетті емес `id`. Бөлгіш — үтір немесе нүктелі үтір. Оқушы `id`
бойынша, ол болмаса дәл аты бойынша табылады. Кетіп қалған оқушыны ашып,
«В архив» (мұрағатқа) батырмасын басыңыз (тарихы сақталады).

**Байланыстыру күні.** «Ученики» → «Создать ссылки для всех непривязанных»
(байланыстырылмағандардың бәріне сілтеме жасау) → сілтемелері бар бетті басып
шығарыңыз. Әр сілтемені оқушының өзіне жеке беріңіз: оны бірінші ашқан адам
сол оқушы болып байланыстырылады. Telegram бағанының жасыл түске
айналғанын бақылаңыз; жоғарғы жолда нешеуі қалғаны көрсетіледі.

**Телефон жоғалды / жаңа аккаунт / басқа адам байланыстырылып қойды.**
Оқушыны ашыңыз → «Отвязать» (байланысты үзу, себебін жазыңыз) → «Новая
ссылка» (жаңа сілтеме) → оны жеке беріңіз.

**Келуді түзету немесе жазылмай қалғанын қосу** (әкімшілер). Оқушыны ашып,
келуді табыңыз → «Изменить» (өзгерту) немесе «Удалить» (жою), не болмаса
төмендегі «Добавить пропущенное посещение» (жазылмай қалған келуді қосу).
Себебін жазу міндетті. Бастапқы жазба өзгермейді; түзету «Исправления»
(түзетулер) бөлімінде және Журналда көрінеді.

**Сағаттар.** «Часы» → күн / апта / ай және топ → дәл сол сандары бар
«Скачать CSV» (CSV жүктеу). Түн ортасынан өтетін келулер екі күнге бөлінеді.

**Аномалиялар** (аптасына бір рет). Баяу сканерлеу немесе ескі кодты
сканерлеу — экранның суреті не трансляциясы болуы мүмкін. «Один ученик на
нескольких ПК» (бір оқушы бірнеше компьютерде) — Telegram аккаунтын басқаға
берген болуы мүмкін. «Несколько учеников в одном сеансе ПК» (бір сеанста
бірнеше оқушы) — жаңа белгілену алдыңғы оқушының келуін жапты деген сөз.
Әдетте бұл жүйеден шықпай орын ауыстыру, бірақ тексерген жөн. «Автоматически
закрытые» (автоматты жабылғандар) сағат 04:00-де әлі ашық болған, аяқталу
уақытын тексеріңіз. «Неудачные сканы» — қабылданбаған әрекеттер.

Жаңа интерфейстің «Аномалии» қойындысында таңдалған кезең бойынша (әдепкіде
ағымдағы апта) тағы төрт тізім бар:

* «Сессии с низкой активностью» (белсенділігі төмен сеанстар): белсенділік
  сәттерінің арасында үнемі ұзақ үзіліс болады (медианалық үзіліс 10 минут
  және одан көп). Компьютерді жүйеден шықпай тастап кеткен болуы мүмкін.
* «Длинные сессии» (ұзақ сеанстар): 6 сағаттан ұзақ келулер.
* «Поздние сканы» (кеш сканерлеу): 21:00 мен 05:00 арасындағы белгіленулер.
* «Сессии с 2–3 аномалиями»: осы тізімдердің екеуіне немесе үшеуіне түскен келулер.

Шектер `attendance.conf` файлында беріледі (`anomaly_low_activity_gap`,
`anomaly_long_visit`, `anomaly_late_from`, `anomaly_late_to`).

## Қызметкерлердің есептік жазбалары (серверде)

```bash
sudo -u attendance attendance user add maria -role teacher -config /etc/attendance/attendance.conf
sudo -u attendance attendance user add aidar -role admin   -config /etc/attendance/attendance.conf
sudo -u attendance attendance user passwd maria -config /etc/attendance/attendance.conf
sudo -u attendance attendance user disable maria -config /etc/attendance/attendance.conf
```

Оқытушылар (`teacher`) әрекеттер журналынан басқаның бәрін көреді;
әкімшілер (`admin`) деректерді өзгерте де алады.

## Жаңарту

Серверде, жүйе жүктелген бумада соңғы нұсқаны алып, орнатқышты қайта іске
қосыңыз. Ол бұрынғы жауаптарды есте сақтайды.

```bash
cd attendance-checker && git pull
./deploy/install.sh                  # сервер және компьютерлердегі агент (компьютерлер алдында растау сұрайды)
./deploy/install.sh --pcs-only       # тек оқу компьютерлері, мысалы біреуін қайта орнатқаннан кейін
./deploy/install.sh --limit pc-01    # алдымен агентті бір компьютерде байқап көру
```

Өшірулі тұрған компьютерлер соңында қайталау командасымен бірге тізіледі.

## Қайта іске қосу, журналдар, кері қайтару

```bash
systemctl status attendance              # жұмыс істеп тұр ма?
sudo systemctl restart attendance        # сервер мен ботты қайта іске қосу (бірнеше секунд сканерлеу өтпейді)
journalctl -u attendance --since today   # журналдар
```

Сәтсіз жаңартудан кейін кері қайтару:
`sudo mv /usr/local/bin/attendance.prev /usr/local/bin/attendance && sudo systemctl restart attendance`.

Қызмет ақаудан кейін өзі қайта қосылады, ал сервер электр қуаты өшіп
қосылғанда өзі іске қосылуы керек (BIOS баптауы). Жаңарту мен қайта іске
қосуды тыныш уақытта жасаңыз.

## Сақтық көшірмелер

Әр түні сағат 03:30-да дерекқордың көшірмесі `/var/backups/attendance`
бумасына жазылады, соңғы 14 көшірме сақталады. Бұл буманы басқа компьютерге
үнемі көшіріп тұрыңыз. Бот токенінің көшірмесін де қауіпсіз жерде сақтаңыз.

Қалпына келтіру: `sudo systemctl stop attendance`, көшірмені
`/var/lib/attendance/attendance.db` үстіне көшіріңіз (иесі `attendance`),
қасындағы `attendance.db-wal` және `attendance.db-shm` файлдарын жойыңыз,
содан кейін қызметті іске қосыңыз.

## Хабарландырулар

Орнату кезінде хабарландыру ID-лері көрсетілсе (өзгерту:
`./deploy/install.sh --reconfigure`), сервер қолжетімсіз болғанда, бот
Telegram-мен байланыса алмағанда немесе компьютерлер сеанс ортасында сигнал
жіберуді тоқтатқанда қызметкерлерге Telegram-да хабар келеді. Боттың `/id`
командасы сіздің Telegram ID-іңізді көрсетеді.
