# Инструкция для сотрудников

[English](staff-runbook.md) · **Русский** · [Қазақша](staff-runbook.kk.md)

Админка: `http://<сервер>:8080/admin` (только из школьной сети, не с учебных ПК).

Интерфейсов два. Переключатель справа вверху переходит между ними, а при
следующем входе откроется тот, которым пользовались последним.

* **Дашборд** (новый): часы, присутствующие ученики, загрузка по часам и дням
  недели, матрица посещаемости и таблица всех учеников за выбранный период
  (по умолчанию текущая неделя; у матрицы свой период, по умолчанию текущий
  месяц). Вкладки: Ученики, Аномалии и Журнал (для администраторов), с теми же
  действиями, что на старых страницах.
* **Админка** (старый): Сегодня, Часы, Ученики, Аномалии и Журнал, как описано ниже.

## Утренняя проверка (30 секунд)

Откройте **Сегодня** и посмотрите на четыре карточки вверху:

| Карточка | Всё в порядке | Стоит разобраться |
|---|---|---|
| Последний сигнал от ПК | минуты назад (в часы работы) | часы назад, хотя в классе были ученики |
| Последняя отметка | сегодня | ничего со вчера, хотя ученики приходили |
| Бот последний раз связывался с Telegram | меньше минуты назад | красная ошибка или «никогда» |
| Открытых посещений | совпадает с тем, кто в классе | — |

В таблице ПК жёлтые строки — компьютеры с сеансом, но без отметки. Напомните этим ученикам отсканировать код.

Если что-то не так, проверьте, работает ли служба (раздел «Перезапуск»).
Посещения, пропущенные из-за сбоя, внесите как исправления (ниже).

## Частые задачи

**Импорт или обновление списка учеников.** Ученики → «Импорт или обновление из CSV».
Столбцы: `имя`/`ФИО`, `группа`, необязательный `id`. Разделитель — запятая или точка с запятой.
Ученики ищутся по `id`, а без него по точному имени. Ушедшего ученика откройте и нажмите «В архив» (история сохранится).

**День привязки.** Ученики → «Создать ссылки для всех непривязанных» → распечатайте страницу со ссылками.
Выдавайте каждую ссылку лично: кто первым её откроет, тот и будет привязан.
Следите, как столбец Telegram становится зелёным; строка сверху показывает, сколько осталось.

**Потерян телефон / новый аккаунт / привязан не тот человек.** Откройте ученика →
«Отвязать» (с причиной) → «Новая ссылка» → выдайте её лично.

**Исправить посещение или добавить пропущенное** (администраторы). Откройте ученика,
найдите посещение → «Изменить» или «Удалить», либо «Добавить пропущенное посещение» внизу.
Причина обязательна. Исходная запись не меняется; исправление видно в разделе «Исправления» и в Журнале.

**Часы.** Часы → день / неделя / месяц и группа → «Скачать CSV» с теми же цифрами.
Посещения через полночь делятся между двумя днями.

**Аномалии** (раз в неделю). Медленные сканы или сканы старого кода — возможно фото или трансляция экрана.
«Один ученик на нескольких ПК» — возможно, аккаунт Telegram передали другому.
«Несколько учеников в одном сеансе ПК» значит, что новая отметка закрыла посещение предыдущего ученика. Обычно это смена ученика без выхода из системы, но стоит проверить.
«Автоматически закрытые» — были открыты в 04:00, проверьте время окончания. «Неудачные сканы» — отклонённые попытки.

На вкладке «Аномалии» нового интерфейса есть ещё четыре списка за выбранный
период (по умолчанию текущая неделя):

* «Сессии с низкой активностью»: постоянные большие перерывы между моментами
  активности (медианный перерыв 10 минут и больше). Возможно, компьютер оставили
  без выхода из системы или что-то не даёт ему уйти в простой.
* «Длинные сессии»: посещения дольше 6 часов.
* «Поздние сканы»: отметки между 21:00 и 05:00.
* «Сессии с 2–3 аномалиями»: посещения, попавшие в два или три из этих списков.

Пороги задаются в `attendance.conf` (`anomaly_low_activity_gap`,
`anomaly_long_visit`, `anomaly_late_from`, `anomaly_late_to`).

## Учётные записи сотрудников (на сервере)

```bash
sudo -u attendance attendance user add maria -role teacher -config /etc/attendance/attendance.conf
sudo -u attendance attendance user add aidar -role admin   -config /etc/attendance/attendance.conf
sudo -u attendance attendance user passwd maria -config /etc/attendance/attendance.conf
sudo -u attendance attendance user disable maria -config /etc/attendance/attendance.conf
```

Преподаватели видят всё, кроме журнала действий; администраторы могут ещё и изменять данные.

## Обновление

На сервере, в папке, куда скачана система, получите последнюю версию и
запустите установщик ещё раз. Прошлые ответы он помнит.

```bash
cd attendance-checker && git pull
./deploy/install.sh                  # сервер и агент на ПК (перед ПК спросит подтверждение)
./deploy/install.sh --pcs-only       # только учебные ПК, например после переустановки одного
./deploy/install.sh --limit pc-01    # сначала попробовать агент на одном ПК
```

Выключенные ПК будут перечислены в конце вместе с командой для повтора.

## Перезапуск, логи, откат

```bash
systemctl status attendance              # работает?
sudo systemctl restart attendance        # перезапуск сервера и бота (сканы не проходят несколько секунд)
journalctl -u attendance --since today   # логи
```

Откат после неудачного обновления: `sudo mv /usr/local/bin/attendance.prev /usr/local/bin/attendance && sudo systemctl restart attendance`.

Служба перезапускается сама после сбоя, а сервер должен включаться после пропадания питания (настройка BIOS).
Обновляйте и перезапускайте в тихие часы.

## Резервные копии

Каждую ночь в 03:30 копия базы пишется в `/var/backups/attendance`, хранятся последние 14.
Регулярно копируйте эту папку на другой компьютер. Храните также копию токена бота и Ansible vault.

Восстановление: `sudo systemctl stop attendance`, скопируйте копию поверх
`/var/lib/attendance/attendance.db` (владелец `attendance`), удалите рядом `attendance.db-wal` и `attendance.db-shm`, запустите службу.

## Оповещения

Если при установке указаны ID для оповещений (изменить: `./deploy/install.sh --reconfigure`)
или в Ansible задан `attendance_alert_chat_ids`, сотрудники получат сообщение в Telegram, когда сервер недоступен,
бот не может связаться с Telegram или ПК перестали присылать сигналы посреди сеанса. Команда бота `/id` показывает ваш Telegram ID.
